# Steering Rack — керування рейкою через реле + потенціометр

Інтеграція лінійного рульового актуатора (рейки) в ArduRover без Arduino.
Замість окремого мікроконтролера — пряме керування через GPIO реле JarvisH743 з
зворотним зв'язком по потенціометру через вбудований ADC STM32H743.

**Вирівнювання по потенціометру опційне** — вмикається й вимикається на льоту
з пульта або з GCS, без перепрошивки. Див. [Режими роботи](#режими-роботи).

> Покрокове підключення, мапінг RC-каналів і повний список параметрів —
> у [STEERING_RACK_SETUP.md](STEERING_RACK_SETUP.md).

---

## Архітектура

```
ArduPilot (SRV_Ch1 steering PWM)
        │
        ▼
  steering_rack.lua          ← Lua скрипт, 20 Hz
  ┌─────────────────────┐
  │ PWM → target voltage │
  │ pot_v = ADC read     │
  │ bang-bang control    │
  └──────┬──────────────┘
         │
    ┌────┴────┐
    ▼         ▼
RELAY1(PE8)  RELAY2(PE7)     ← GPIO outputs (3.3V logic)
    │             │
    ▼             ▼
  LEFT          RIGHT         ← Motor driver / relay module
    └──────┬───────┘
           ▼
     Steering rack motor

PB0 (ADC1_INP9) ←──── Potentiometer (0–3.3V)
```

## Зміни в hwdef.dat

### Увімкнення ADC

```ini
# До:
define HAL_USE_ADC FALSE
define STM32_ADC_USE_ADC1 FALSE
define HAL_DISABLE_ADC_DRIVER TRUE

# Після:
define STM32_ADC_USE_ADC1 TRUE
PB0 ADC1 ADC1
```

### Переконфігурація реле (PB0 звільнено під ADC)

```ini
# До:
PB0  PINIO1 OUTPUT GPIO(71) LOW   ← тепер ADC
PB1  PINIO2 OUTPUT GPIO(72) LOW
PB2  PINIO3 OUTPUT GPIO(73) LOW
PE7  PINIO4 OUTPUT GPIO(74) LOW
PE8  PINIO5 OUTPUT GPIO(75) LOW

define RELAY1_PIN_DEFAULT 75
define RELAY2_PIN_DEFAULT 74
define RELAY3_PIN_DEFAULT 73
define RELAY4_PIN_DEFAULT 72
define RELAY5_PIN_DEFAULT 71

# Після:
PB1  PINIO1 OUTPUT GPIO(71) LOW
PB2  PINIO2 OUTPUT GPIO(72) LOW
PE7  PINIO3 OUTPUT GPIO(73) LOW
PE8  PINIO4 OUTPUT GPIO(74) LOW

define RELAY1_PIN_DEFAULT 74  # PE8 — LEFT
define RELAY2_PIN_DEFAULT 73  # PE7 — RIGHT
define RELAY3_PIN_DEFAULT 72  # PB2
define RELAY4_PIN_DEFAULT 71  # PB1
```

> **RELAY5 (PB0) більше не існує** — пін перероблено на ADC вхід.

## Підключення

### Потенціометр → FC

| Потенціометр | JarvisH743 |
|---|---|
| + живлення | 3.3V |
| – живлення | GND |
| Wiper (середній вивід) | **PB0** (ADC1_INP9) |

> Потенціометр має бути розрахований на напругу 3.3V. Якщо живиться від 5V —
> потрібен дільник напруги або рейка буде пошкоджена!

### Реле / H-bridge → FC

| Сигнал | Пін FC | GPIO | Реле AP |
|---|---|---|---|
| LEFT direction | **PE8** | 74 | RELAY1 |
| RIGHT direction | **PE7** | 73 | RELAY2 |

> Виходи PE8/PE7 — **3.3V логіка**, не призначені для прямого керування реле.
> Обов'язково потрібен драйвер: relay module (з оптронами) або H-bridge (L298N, BTS7960 тощо).

## Lua скрипт

**Файл:** `libraries/AP_HAL_ChibiOS/hwdef/JarvisH743/scripts/steering_rack.lua`

### Логіка роботи — вирівнювання УВІМКНЕНЕ (`JRVS_RACK_OL = 0`)

1. Читає `SRV_Channels` output ch1 (GroundSteering, `SERVO1_FUNCTION=26`) — бажаний кут
2. Маппить PWM (1100–1900 мкс) → цільова напруга потенціометра
3. Читає поточну напругу потенціометра (PB0, ADC1_INP9)
4. Bang-bang: вмикає LEFT або RIGHT реле поки похибка > deadband
5. Зупиняє реле при досягненні цілі або апаратних меж рейки

### Логіка роботи — вирівнювання ВИМКНЕНЕ (`JRVS_RACK_OL = 1`)

1. Потенціометр не читається взагалі
2. Реле йдуть напряму від стіка: лівіше центру → LEFT, правіше → RIGHT, у центрі → стоп
3. Оператор підрулює сам, на око

Логіка реле в обох режимах однакова — різниться тільки джерело рішення «стоп».

### Захист

- Перевірка pot_v < 0.1V або > 3.3V → зупинка + повідомлення в GCS (fault)
- Апаратні межі: зупинка при pot_v ≤ V_MIN+50мВ або ≥ V_MAX-50мВ

> Обидва захисти працюють **тільки при увімкненому вирівнюванні**. У режимі
> `JRVS_RACK_OL = 1` рейка тримається на власних механічних упорах — не залишайте
> стік у крайньому положенні надовго.

## Параметри GCS (вкладка JRVS_)

| Параметр | За замовч. | Опис |
|---|---|---|
| `JRVS_RACK_V_MIN` | 2.00 | Напруга потенціометра на лівому упорі (V) |
| `JRVS_RACK_V_CTR` | 2.62 | Напруга в центральному положенні (V) |
| `JRVS_RACK_V_MAX` | 3.26 | Напруга на правому упорі (V) |
| `JRVS_RACK_DB_C`  | 0.07 | Deadband коли рейка в центрі (V) |
| `JRVS_RACK_DB_M`  | 0.04 | Deadband під час руху до цілі (V) |
| `JRVS_RACK_OL`    | 0    | Вирівнювання: **0 = увімкнене** (closed loop), **1 = вимкнене** (open loop) |

> Зміна параметрів через GCS **не потребує перезбірки** firmware.

## Режими роботи

| `JRVS_RACK_OL` | Режим | Потенціометр | Хто вирішує «стоп» |
|---|---|---|---|
| `0` | Вирівнювання увімкнене | читається | скрипт (ціль + апаратні межі) |
| `1` | Вирівнювання вимкнене | ігнорується | оператор стіком |

Режим зберігається в параметрі, тому тримати перемикач не треба: виставив — і воно
так лишається, включно з перезавантаженням (запис через `set_and_save`).

### Спосіб 1 — тумблер на пульті (CRSF)

Одноразове налаштування, коду не потребує:

1. Обрати вільний RC-канал і виставити `RCn_OPTION = 300` (Scripting1).
   Штатно це **CH12**: `RC12_OPTION = 300`
2. На пульті призначити на цей канал **3-позиційний** тумблер

Скрипт читає позицію aux-функції (пороги ArduPilot: `<1200 мкс` = LOW,
`>1800 мкс` = HIGH, між ними = MIDDLE):

- **HIGH** → вирівнювання УВІМКНЕНО (`JRVS_RACK_OL = 0`)
- **LOW** → вирівнювання ВИМКНЕНО (`JRVS_RACK_OL = 1`)
- **MIDDLE** → нічого не робить, режим лишається як був

> Чому саме 3-позиційний: середнє положення означає «ніхто не командує каналом».
> Воно потрібне, щоб GCS (спосіб 3) міг перехопити канал, а після втрати зв'язку
> віддати його назад, не перемкнувши при цьому режим. Якщо тумблер на пульті не
> потрібен взагалі — просто не призначайте цей канал на передавачі, тоді він
> віддає нейтраль і каналом керує тільки GCS.

### Спосіб 2 — параметр з GCS

Записати `JRVS_RACK_OL` = `0` або `1` у будь-якому GCS (Mission Planner,
QGroundControl, AetherLink). Працює завжди, навіть без RC-приймача.

### Спосіб 3 — кнопка в AetherLink (GS-WEB)

У панелі Quick Actions додати кнопку:

| Поле | Значення |
|---|---|
| Action | `RC Override TOGGLE…` |
| RC channel | номер каналу з `RCn_OPTION = 300` |
| ON PWM | `2000` |

Тогл дає 2000 мкс (ON) / 1000 мкс (OFF) — це рівно HIGH / LOW для aux-функції.
GS-WEB перевідправляє оверрайд кожні 50 мс, тому 3-секундний
`RC_OVERRIDE_TIME` не встигає спрацювати; оверрайд живе і без підключеного
геймпада, і переживає перезавантаження сторінки.

**Хто останній, той і правий.** Пульт і GCS пишуть один і той самий параметр,
жодному не треба «утримувати» стан. Якщо AetherLink закрили або зв'язок впав
довше ніж на 3 с — канал повертається пульту, той віддає нейтраль (MIDDLE), і
режим просто лишається останнім обраним.

### Підтвердження в GCS

Скрипт пише в Messages при кожній зміні:

```
RACK: alignment ON (switch)      ← перемкнули тумблером/кнопкою
RACK OL p=1500 pot=2.62 d=0 (pot ignored)   ← ~1 Гц, вирівнювання вимкнене
RACK p=1500 pot=2.62 e=+0.00 d=0            ← ~1 Гц, вирівнювання увімкнене
```

### Діагностика несправності

Режим `JRVS_RACK_OL = 1` заодно відділяє проблему потенціометра від проблеми
реле/плати/мотора:

- Рейка **рухається** з вимкненим вирівнюванням → проблема в потенціометрі або
  проводці до нього (силова частина — реле, проводка, мотор — справна).
- Рейка **не рухається** і так → потенціометр ні до чого, шукайте проблему в
  реле / проводці до мотора / самому моторі.

## Калібрування (після першої прошивки)

1. Переконатись що `SERVO1_FUNCTION = 26` (GroundSteering)
2. Переконатись що `RELAY1_FUNCTION = 1` і `RELAY1_PIN = 74`, `RELAY2_FUNCTION = 1` і `RELAY2_PIN = 73`
   (без `FUNCTION = 1` реле мовчать, а скрипт при цьому не видає жодної помилки)
3. Відкрити MAVLink Inspector або Serial Monitor
4. Встановити рейку вручну в крайнє **ліве** положення → записати pot_v → вписати в `JRVS_RACK_V_MIN`
5. Встановити рейку в **центр** → записати pot_v → `JRVS_RACK_V_CTR`
6. Встановити рейку в крайнє **праве** положення → записати pot_v → `JRVS_RACK_V_MAX`
7. Зберегти параметри (Write) в GCS
8. Перевірити напрямок: якщо LEFT і RIGHT переплутані — поміняти `RELAY_LEFT` і `RELAY_RIGHT` в скрипті або переключити проводку
9. (Опційно) Налаштувати перемикач вирівнювання: `RCn_OPTION = 300` на вільному каналі — див. [Режими роботи](#режими-роботи)

## Порівняння з Arduino-рішенням

| | Arduino (було) | JarvisH743 Lua (є) |
|---|---|---|
| Зчитування PWM | Pin-change ISR | ArduPilot SRV_Channels |
| Режими MANUAL/AUTO | CH_MODE PWM | ArduPilot flight mode |
| Потенціометр | analogRead A0 (10-bit) | ADC1_INP9 (16-bit) |
| Реле керування | digitalWrite D6/D10 | relay:on/off (RELAY1/2) |
| Параметри | Хардкод у коді | GCS параметри JRVS_* |
| Пристроїв | 2 (FC + Arduino) | 1 (тільки FC) |
