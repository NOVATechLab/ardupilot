# Can-Am ATV — CAN Map (для інтеграції в ArduPilot)

**Джерело:** реверс осцилограм логічного аналізатора, BUDS2 Service Level 3, VIN 3JB3RA587TJ000316
**Дата:** 2026-08-15
**Метод:** пасивне прослуховування CAN + порівняння записів у різних станах

## Параметри шини

| Параметр | Значення |
|---|---|
| Бітрейт | 500 кбіт/с |
| Формат ID | 11-бітний (standard) |
| Порядок байтів | Big-endian |
| Завантаження шини | ~25–30 % |
| Час до появи всіх модулів після подачі живлення | ~280 мс |

Спільна структура критичних повідомлень (0x103, 0x309, 0x121):
`[дані...] [B6: кільцевий лічильник 0–F] [B7: XOR байтів B0–B6]`

---

## 1. Педаль газу — 0x103 (10 мс) ✅ пасивно

| Байт | Сигнал | Кодування |
|---|---|---|
| B0 | **Accelerator Pedal Position** | 0x00 = 0 %, 0xFE = 100 % (÷2.54) |
| B3 | Статус педалі | біт 6: 1 = натиснута |
| B6 low nibble | Лічильник | 0x0–0xF |
| B7 | Чексум | XOR B0–B6 |

Сирі мВ датчика (APP1/APP2) на шину НЕ транслюються — тільки готовий %.

## 2. Селектор КПП — 0x309 (10 мс) ✅ пасивно

Байти B0 = B1 (дубль), one-hot:

| Значення | Положення |
|---|---|
| 0xC0 | P (Park) |
| 0x80 | N (Neutral) |
| 0x40 | R (Reverse) |
| 0x20 | H (High) |
| 0x10 | L (Low) |

Валідне значення = 1 або 2 біти (2 лише для Park). Інше = помилка датчика.

## 3. Стан приводу 2WD/4WD — 0x400 B5 (21 мс) ✅ пасивно

| Значення | Режим |
|---|---|
| 0x00 | **2WD** (задній) |
| 0x10 | **4WD** (повний) — біт 4 |

Утримуваний стан актуатора роздатки. Перемикається ПІСЛЯ натискання кнопки із затримкою на відпрацювання механізму. Підтверджено записом 2WD→4WD→2WD→4WD.
Повний payload: `00 00 3D 00 00 {00|10} ...`

## 4. Блокування переднього валу/діфа — 0x103 B3 біт0 (10 мс) ✅ пасивно 🔶 1 запис

| Значення | Стан |
|---|---|
| біт0 = 0 | вал розблокований |
| біт0 = 1 | **вал заблокований** |

Дубль: **0x121 B0 біт0** (20 мс) — те саме значення.
Підтверджено крос-перевіркою: біт0 = 0 у всіх інших записах, стає 1 лише при реальному клацанні тумблера блокування. Рекомендується перевірити ще одним записом.

Стан «Switching» (перехідний) у broadcast чітко не виділяється — можливо, дуже короткий або діагностичний. Для практики: Locked/Unlocked читається надійно, перехід = "біт щойно змінився".

0x102 B2 (раніше вважався кнопкою) — це глітчі ~10 мс, НЕ надійний сигнал, не використовувати.

## 5. Рульова рейка DPS — діагностика ⚠️ тільки за запитом

**Запит:** ID `0x7C3`, дані `03 22 <DID_H> <DID_L> 55 55 55 55`
**Відповідь:** ID `0x7CB`, дані `LL 62 <DID_H> <DID_L> <VAL BE...> 00...`

| DID | Параметр | Масштаб |
|---|---|---|
| 0x1020 | Bridge Temperature | 1 °C/біт |
| 0x1021 | PCB Temperature | 1 °C/біт |
| 0x1030 | Torque Raw | 0.01 Нм/біт |
| 0x1031 | Torque User | 0.01 Нм/біт |
| 0x1032 | Steering Torque Offset | 0.01 Нм/біт |
| **0x1033** | **Motor Current** | 0.1 А/біт |
| 0x1035 | Motor Current Target | 0.1 А/біт |
| 0x1037 | Motor UVW→Encoder Idx Offset | ÷1600 = град |
| 0x1039 | Motor→Encoder Offset | ÷1600 = град |

Приклад: `7C3 # 03 22 10 33 ...` → `7CB # 05 62 10 33 01 D6 00 00` → 0x01D6=470 → **47.0 А**.

## 6. Оберти двигуна — 0x102 B2-3 (BE, 10 мс) ✅ пасивно

**RPM = (B2<<8 | B3)** (масштаб близький до 1:1, точний коеф. уточнити по тахометру BUDS).
Перевірено: холостий (педаль=0) = стабільно 1657; при газуванні йде точно за педаллю (1657 → 4000+). Динаміка обертів слідує за педаллю газу.

## 6b. Навантаження двигуна(?) — 0x103 B5 🔶 кандидат

130 на холостому → 168-184 під навантаженням при русі. Ймовірно engine load / момент. Масштаб не встановлено.

## 7. Швидкість — 0x231 B0-1 (BE, 11 мс) ✅ пасивно

**Швидкість (км/год) = (B0<<8 | B1) / 10** (0.1 км/год на біт).
Дубль: **0x312 B4-5 (BE)** — те саме значення.
Перевірено записом руху: плато raw≈40 = 4.0 км/год. На стоянці = 0.

**Одометр:** у broadcast не знайдено — ймовірно тільки діагностика. Формальні "монотонні" кандидати виявились лічильниками кадрів, не пробігом.

## 8. Рівень палива — 0x530 B4 (100 мс) ✅ пасивно

Робоче значення ~raw% (33-38 у різних записах). **0x7F (127) = обрив/відключення датчика.**
Підтверджено записом відʼєднання: датчик підключений = 0x21-0x22, відʼєднаний = 0x7F (11 сек), знову підключений = 0x22. Масштаб близький до 1:1 з відсотками (уточнити).

## 9. Флаг помилки паливного датчика — 0x342 B2-B3 (20 мс) ✅ пасивно

| B2:B3 | Стан |
|---|---|
| 99 99 | норма (немає помилки) |
| 06 27 | **обрив/несправність датчика палива** |

Підтверджено: 99 99 у всіх нормальних записах, 06 27 рівно у вікні відключення датчика. Реагує швидше за сам сигнал палива (20 мс проти 100 мс).

## 10. Напруга акумулятора — 0x342 B4 (20 мс) ✅ пасивно

**Напруга (В) = B4 × 0.1**
Перевірено по всіх записах: стояв (key ON) = 128-130 (12.8-13.0 В, збіг з BUDS 12.88 В); двигун працює = 141-143 (14.1-14.3 В, напруга зарядки генератора). Фізично коректна поведінка.

**Примітка:** раніше 0x342 B4 у записах КПП (82/83/84 = 130-132) помилково прийнято за індикатор передачі — насправді це завжди була напруга (13.0-13.2 В).

**⚠️ Відкликано:** 0x300 B5-6 раніше помилково позначався як RPM — насправді це артефакт (лічильник B6 + сусідній байт), гуляє на нерухомій машині без газу. Справжні оберти в 0x102 B2-3.

## Що з BUDS2 і без нього

| Параметр | Джерело | Заводський OBD потрібен? |
|---|---|---|
| Педаль газу | 0x103 B0 | Ні |
| Селектор КПП | 0x309 | Ні |
| Стан 2WD/4WD | 0x400 B5 | Ні |
| Блокування пер. валу | 0x103 B3 біт0 | Ні |
| Оберти двигуна | 0x102 B2-3 | Ні |
| Швидкість | 0x231 B0-1 (÷10) | Ні |
| Рівень палива | 0x530 B4 (0x7F=обрив) | Ні |
| Помилка датчика палива | 0x342 B2-B3 | Ні |
| Напруга акумулятора | 0x342 B4 (×0.1В) | Ні |
| Момент/струм рейки | діаг 7C3/7CB | Запит так, сканер ні |

Для пасивних параметрів заводський BUDS2 НЕ потрібен. Для DPS та (ймовірно) стану діфа треба самим слати UDS-запити — ArduPilot це вміє, сканер не потрібен.

---

## Диференціал: статус пошуку

**Знайдено:** кнопка діфа (0x102 B2) — подія натискання.
**НЕ знайдено:** утримуваний стан Lock / Unlock / Switching у broadcast.

Порівняння стану шини на початку і в кінці запису перемикання діфа — ідентичне, жоден байт не лишився в новому стані. Стан діфа, найімовірніше, читається UDS-запитом (як DPS), а не мовиться на шину.

**Щоб дожати — потрібен запис, де в логу ВИДНО діагностичний трафік (0x7Cx) одночасно зі зміною стану діфа на екрані BUDS.** Тоді витягується DID і три коди станів. Якщо діагностики в такому логі немає — значить BUDS читає діф іншим каналом, і для ArduPilot стан діфа доведеться брати з фізичного проводу актуатора.

## Псевдокод декодування (ArduPilot CANSensor)

```c
switch (frame.id) {

case 0x103:  // педаль газу
    pedal_pct     = frame.data[0] * 100.0f / 254.0f;
    pedal_pressed = (frame.data[3] >> 6) & 1;
    break;

case 0x309: {  // селектор КПП
    uint8_t g = frame.data[0];
    if (g != frame.data[1]) { gear = GEAR_INVALID; break; }
    switch (g) {
        case 0xC0: gear = GEAR_PARK;    break;
        case 0x80: gear = GEAR_NEUTRAL; break;
        case 0x40: gear = GEAR_REVERSE; break;
        case 0x20: gear = GEAR_HIGH;    break;
        case 0x10: gear = GEAR_LOW;     break;
        default:   gear = GEAR_INVALID; break;
    }
    break;
}

case 0x400:  // привід
    drive_mode = (frame.data[5] & 0x10) ? DRIVE_4WD : DRIVE_2WD;
    break;

case 0x103:  // (окрім педалі) флаг блокування переднього валу
    front_shaft_locked = frame.data[3] & 0x01;   // 1 = заблокований
    break;
// дубль того ж флага: 0x121 B0 біт0

case 0x102:  // оберти двигуна (B2-3) + навантаження(?) (B5)
    engine_rpm = (frame.data[2] << 8) | frame.data[3];   // ~1:1, уточнити
    engine_load = frame.data[5];                          // кандидат
    break;

case 0x231:  // швидкість
    vehicle_speed_kmh = ((frame.data[0] << 8) | frame.data[1]) / 10.0f;
    break;

case 0x530:  // рівень палива
    if (frame.data[4] == 0x7F) fuel_sensor_open = true;   // обрив
    else fuel_level_pct = frame.data[4];                   // ~raw%
    break;

case 0x342:  // помилка датчика палива (B2-3) + напруга (B4)
    fuel_sensor_fault = !(frame.data[2]==0x99 && frame.data[3]==0x99);
    battery_voltage = frame.data[4] * 0.1f;   // В
    break;
}
```

Валідація фреймів 0x103/0x309/0x121:
```c
uint8_t x = 0;
for (int i = 0; i < 7; i++) x ^= data[i];
if (x != data[7]) reject();            // чексум
// + лічильник (B6 low nibble) має інкрементуватись
// + таймаут > 100 мс = сигнал stale
```

## Примітки

- Карту знято на стоячій машині. Динамічні сигнали (швидкість, оберти під навантаженням) не калібровано.
- Байти, не згадані як сигнали, можуть нести інші дані — не перезаписувати при передачі.
- Для ПЕРЕДАЧІ команд drive-by-wire треба емулювати лічильник + XOR-чексум, інакше ECM відкине кадр.
